# Gabarit v2 : spécification d'implémentation

Validé par JF le 2026-10-08 (piste 3 : gabarit plus riche, inspiré du skill `image-to-json`).
Objectif : décrire une image existante (ou une image à créer) avec beaucoup plus de détails, sans alourdir le formulaire par défaut.

## Principes
1. Le formulaire actuel reste l'**essentiel**, inchangé. Les nouveaux champs vont dans une section repliée « Détails avancés (facultatif) ».
2. **Compatibilité** : un JSON v1 (déjà enregistré en base) s'ouvre sans perte, converti en v2 par `normaliserGabarit`. Quand les nouveaux champs sont vides, `composePrompt` produit EXACTEMENT le même texte qu'avant (les tests actuels de `composePrompt` doivent rester verts sans modification de leurs attentes).
3. Tous les nouveaux champs sont facultatifs, en texte libre (500 caractères maximum chacun).
4. Chaque nouveau champ de formulaire a : un label précis, un placeholder concret avec exemple réel du contexte FWB, un texte d'aide sous le champ expliquant l'effet de la saisie. Aucune affirmation sur l'apprentissage ni référence scientifique. Ne jamais suggérer de décrire un élève réel.
5. Pas d'emojis. Imports relatifs avec extension `.js`.

## Schéma v2 (`schema_version: 2`)
```json
{
  "schema_version": 2,
  "sujet": { "description": "", "details": "" },
  "elements": [ { "nom": "", "position": "", "details": "" } ],
  "style": { "type": "", "palette": "" },
  "couleurs": { "dominantes": "", "saturation": "", "contraste": "", "harmonie": "" },
  "composition": { "cadrage": "", "point_de_vue": "", "arriere_plan": "", "profondeur": "", "plans": "", "symetrie": "" },
  "lumiere": "",
  "eclairage": { "source": "", "direction": "", "qualite": "", "temperature": "", "ombres": "" },
  "decor": { "lieu": "", "moment": "", "meteo_saison": "", "elements": "" },
  "atmosphere": "",
  "textes": [ { "contenu": "", "position": "", "style": "" } ],
  "rendu": { "nettete": "", "textures": "", "grain": "" },
  "mouvement": "",
  "exclusions": ["pas de texte dans l'image"],
  "format": { "ratio": "1:1" },
  "generation": { "seed": null },
  "personnalise": [ { "nom": "", "valeur": "" } ]
}
```
Limites : chaque texte 500 caractères ; `elements` 15 entrées maximum (entrée ignorée si `nom` vide) ; `textes` 10 maximum (ignorée si `contenu` vide) ; `exclusions` et `personnalise` 10 maximum comme avant.
`gabaritVide()` renvoie ce schéma avec `elements: []`, `textes: []` et tous les textes vides.

## `normaliserGabarit` (src/lib/gabarit.js)
- Accepte v1 ou v2 ; sortie toujours en v2 (`schema_version: 2`).
- Clés connues = les 17 clés ci-dessus ; toute autre clé de premier niveau va dans `personnalise` avec avertissement (comportement actuel inchangé).
- Chaque groupe (`couleurs`, `composition`, `eclairage`, `decor`, `rendu`) : ne retenir que ses sous-clés connues, texte nettoyé, `''` par défaut. `atmosphere`, `mouvement`, `lumiere` : texte.
- `elements` et `textes` : tableau d'objets ; ignorer ce qui n'est pas un objet ; ignorer les entrées sans `nom` / sans `contenu` ; tronquer les textes ; respecter les maximums.
- `validerPourGeneration` : en plus de « Décrivez le sujet de l'image. », refuser un prompt composé de plus de `PROMPT_MAX_CARACTERES` caractères (constante exportée de gabarit.js, valeur 4000) avec le message `La description est trop longue (N caractères sur 4000) : raccourcissez-la.` (N = longueur réelle). Le serveur applique déjà `validerPourGeneration` : aucun changement de handler nécessaire, mais vérifier que `api/_lib/handlers/generate.js` renvoie bien 400 `invalid_json` avec ce message.

## `composePrompt` (src/lib/composePrompt.js)
Ordre des phrases (une ligne vide de valeur est ignorée ; `fin()` ajoute le point final) :
1. sujet.description, sujet.details
2. Éléments : une seule phrase `Éléments : nom1 (position1) : détails1 ; nom2 (position2) ; nom3 : détails3.` (parenthèse et deux-points seulement si renseignés)
3. Style, Palette
4. `Couleurs dominantes`, `Saturation`, `Contraste`, `Harmonie des couleurs`
5. Cadrage, Point de vue, Arrière-plan, `Profondeur de champ`, `Plans présents`, `Symétrie`
6. Lumière, puis `Source de lumière`, `Direction de la lumière`, `Qualité de la lumière`, `Température de la lumière`, `Ombres`
7. `Lieu`, `Moment`, `Météo et saison`, `Éléments du décor`
8. Atmosphère
9. Pour chaque texte : `Texte visible : « contenu » (position, style).` (parenthèse seulement avec ce qui est renseigné)
10. `Netteté`, `Textures`, `Grain`
11. Mouvement
12. personnalise (comme avant), puis `À éviter : …` (comme avant)

## Consigne « partir d'une image » (src/lib/consigneImage.js)
- `SCHEMA_EXEMPLE` = `gabaritVide()` avec `exclusions: []` (donc v2). Le test garantit que `normaliserGabarit(SCHEMA_EXEMPLE)` n'émet aucun avertissement.
- La consigne explique CHAQUE groupe (elements, couleurs, composition avancée, éclairage, décor, atmosphère, textes, rendu, mouvement), demande de laisser `""` ou `[]` quand un détail n'est pas visible (n'invente rien), liste les formats de `format.ratio`, annonce les limites (500 caractères par valeur, 15 éléments, 10 textes, 10 champs personnalisés), garde les règles : réponse JSON seule, n'identifie aucune personne, n'invente rien, guillemets droits interdits dans les valeurs.
- Les « Textes visibles » vont désormais dans le tableau `textes` (plus dans `personnalise`) ; `personnalise` ne sert qu'à ce qui n'a vraiment aucun champ.

## Formulaire (src/lib/champs.js, src/components/GabaritForm.jsx)
- Nouveaux champs avec `avance: true` et `section` (libellé du sous-groupe) : Éléments, Couleurs, Composition avancée, Éclairage, Décor, Atmosphère, Textes présents, Rendu et matières, Mouvement.
- Dans le tableau `CHAMPS`, les champs avancés sont contigus, juste après `lumiere`. `GabaritForm` rend les champs essentiels dans l'ordre, et à la place du premier champ avancé un seul `<details>` « Détails avancés (facultatif) » qui contient tous les champs avancés regroupés par `section` (titre de sous-groupe). Le `<details>` est ouvert automatiquement si au moins un champ avancé est renseigné ou verrouillé.
- Listes d'objets (`elements`, `textes`, et `personnalise` existant) : un éditeur générique piloté par configuration (`colonnes: [{ cle, label, placeholder }]`, `max`), avec boutons Ajouter / Retirer, `aria-label` pour chaque cellule, verrouillable (désactive tout).
- Chaque champ avancé est verrouillable par un modèle via son chemin (`couleurs.dominantes`, `elements`, `textes`, etc.) : la page Modèles liste déjà `CHAMPS`, donc rien d'autre à faire si `label` contient le nom du sous-groupe (par exemple « Éclairage : source »).

## Hors périmètre
Pas de conversion du JSON du skill `image-to-json` ; pas de changement de base de données (le JSON est stocké en jsonb) ; pas de nouvelle route d'API ; pas de pagination.
